# 出门也能用：Tailscale 方案

> 目标：人不在家（手机走 4G/5G），也能连上**自己电脑**上跑的网关和 DSH。
> 关键结论：**不需要改代码，也不需要公网 IP**。Tailscale 会给每台设备一个
> 固定的 `100.x.y.z` 地址，手机在任何网络下都能连到这个地址。

---

## 0. 为什么不能直接把 8788 端口开到公网

家用宽带绝大多数是 **CGNAT**（没有自己的公网 IPv4），端口映射根本映射不出去；
就算有公网 IP，现在网关是**纯 HTTP**：设备令牌明文传输，`/v1/health` 与 `/v1/pair`
免鉴权，令牌没有有效期。**把这样的服务怼到公网，等于把钥匙挂门把手上。**

Tailscale 解决的就是这件事：一条端到端加密的私有网络，只有登录了同一个账号的
设备才能互相看见，公网扫不到你的 8788。

---

## 1. 电脑端（Windows）

1. 装 Tailscale：<https://tailscale.com/download/windows>，安装后用**同一个账号**登录
   （Google/GitHub/邮箱都行，个人版免费）。
2. 记下这台电脑的 Tailscale 地址（形如 `100.101.102.103`）：
   - 托盘图标右键 → 点自己的设备名，能看到 IP；
   - 或在命令行：`tailscale ip -4`
3. 确认它出现在网卡列表里（网关的启动横幅会自动打印）：

```bash
cd surfcore/mobile-gateway
node src/main.js --listen 0.0.0.0:8788
```

横幅会打印两类地址，带 `← Tailscale` 标记的就是外出用的：

```
   手机端「网关地址」填下面这个：
   http://192.168.1.247:8788
   http://100.101.102.103:8788   ← Tailscale，外出也能用
```

## 2. 手机端

1. 装 Tailscale（应用商店搜 Tailscale），**登录同一个账号**，打开开关。
2. 打开 DSH App，「网关地址」填 `http://100.101.102.103:8788`（换成你电脑那个 100.x 地址）。
3. 「6 位配对码」填电脑窗口里那 6 位。
4. 配对成功后，以后在家、在公司、在 4G 下都用同一个地址，不用改。

> 建议给电脑设一个固定的 Tailscale 机器名（后台 → Machines → 改 Rename），
> 并把「Key expiry」设成 disable，否则过一段时间设备密钥过期会突然连不上。

---

## 3. 必须知道的四件事

| 事项 | 说明 |
| --- | --- |
| **电脑不能睡** | 合盖/睡眠 = 网络断。电源设置里把「睡眠」改成「从不」或「插入电源时从不」 |
| **网关要一直开着** | 现在没有开机自启/守护。关掉终端窗口网关就停了（`Ctrl+C` 也会停） |
| **DSH 要登录过** | ACP 子进程是全新实例，需要 DSH 本机凭据可用（见 case 文档 §9.4 的密钥问题） |
| **手机要开 Tailscale** | 关掉 Tailscale 开关，App 立刻连不上（这也是安全的一部分） |

---

## 4. 故障排查

| 现象 | 先看什么 |
| --- | --- |
| App 报「连接失败」 | 手机 Tailscale 开关是否打开；电脑 `tailscale status` 是否在线 |
| 能 ping 通但 App 连不上 | 网关是否在跑（`curl http://100.x.y.z:8788/v1/health`），端口是否是 8788 |
| 昨天好好的，今天连不上 | Tailscale 设备密钥过期（后台看 Machines 的 expiry），或电脑睡眠了 |
| 连上了但发消息报错 | 不是网络问题，是 DSH 的模型密钥（case 文档 §9.4） |

自检命令（在电脑上跑，用你手机的 Tailscale 地址反向不好测，直接测本机）：

```bash
curl http://127.0.0.1:8788/v1/health
# 期望：{"ok":true,...,"dsh":{"connected":true,"server":{"name":"deepseek-harness-acp",...}},...}
# 注意 dsh.connected 才是关键；网关先起、DSH 后连是正常顺序，等 3 秒再 curl
```

---

## 5. 一个诚实的取舍

Tailscale 是**「自己给自己用」**的工具：每台设备都要登录账号。这在自用场景是优点
（零配置、加密、不用暴露公网），但在「发布给别人用」的场景下**不能直接套用**——
别人不该登录你的 Tailscale 账号。

如果将来要做成给别人用的产品，网络层有两条路：
1. **让用户自己搭**（文档教他装 Tailscale/ZeroTier，各自用自己的账号）——现实、但门槛高；
2. **做中转服务**（用户设备主动连你的服务器，类似 frp/中继）——体验好，但你要承担
   服务器成本、流量与合规责任，且必须补 TLS、令牌有效期、限流。

现在这一版属于第 1 条，别把它当成第 2 条来宣传。
